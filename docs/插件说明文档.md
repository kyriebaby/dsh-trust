# dsh-trust：DeepSeek Harness 插件安全审计工具

## 概述

`dsh-trust` 是一个面向 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）的第三方安全插件。它的核心任务是回答一个被生态长期忽略的问题：

> **「我 `dsh plugin add` 装进机器的这个插件，到底会对我做什么？」**

DeepSeek Harness 的插件模型是「一切皆插件」，安装一个插件本质上等于在自己的机器上运行一段第三方任意代码——工具审批链能拦住 agent 的动作，却拦不住插件自身的代码。`dsh-trust` 通过确定性的静态分析，把这段"看不见的风险"摊到明面上。

## 它能做什么

- **枚举已装插件**：找出当前 profile 里所有第三方 bundle（非 `@deepseek-ai/` 作用域）。
- **静态解析**：读取每个插件的 `package.json` 与 `cordis.patch.yml`，不执行任何插件代码。
- **计算风险信号**：注入能力面、`!!js` 配置表达式、安装脚本、第三方依赖面。
- **依赖漂移检测**：首次审计记录依赖基线，之后依赖增删/版本变化自动告警。
- **两种使用形态**：对话内工具 `audit_plugins` + Web 设置页「安全审计」面板。

整个过程**纯文件系统、确定性、无网络、无 LLM 参与判定**——结果不依赖模型主观判断。

## 安装

```bash
dsh plugin --profile web add dsh-trust
```

重启 `dsh web` 后生效。安装后会同时注册：

1. 对话工具 `audit_plugins`
2. Web 设置页「安全审计」tab（设置 → 插件 → 安全审计）

## 使用方式一：对话工具 `audit_plugins`

直接在对话里对 agent 说：

> 帮我审计一下当前已装的插件有没有安全风险

agent 会调用 `audit_plugins`，返回每个插件的风险卡（等级 + 风险明细）。可选参数：

| 参数 | 说明 |
|------|------|
| `profile` | 审计指定 profile（默认当前 profile，如 `web` / `headless`） |
| `updateBaseline` | 设为 `true` 时，接受当前依赖状态为新基线（清空漂移告警） |

## 使用方式二：Web 面板「安全审计」

打开 **设置 → 插件 → 安全审计**，面板会列出每个第三方插件的：

- 风险等级徽章（高危 / 可疑 / 干净）
- 安装脚本、host/client 注入能力面
- patch 层摘要（insert/disable 数量、是否含 `!!js`）
- 依赖漂移状态

面板为只读展示，不会修改任何插件或配置。

## 风险信号说明

| 风险信号 | 检测方式 | 触发等级 |
|----------|----------|----------|
| `!!js` 配置表达式 | `cordis.patch.yml` 中出现 `!!js` | 🔴 高危 |
| 安装脚本 | 存在 `install` / `postinstall` / `preinstall` | 🔴 高危 |
| `prepare` 脚本 | 存在 `prepare`（构建期执行，通常正常） | 🟡 可疑 |
| 高权限 host 注入 | 注入了 `subprocess` / `shell` / `dynamicCordisRunner` / `loader` / `sandboxPolicy` / `credentials` | 🟡 可疑 |
| 依赖漂移 | 相对基线的依赖新增 | 🟡 可疑 |
| 宽依赖面 | 第三方依赖超过 10 个 | 🟡 可疑 |

## 依赖漂移

依赖漂移（dependency drift）指插件的依赖集合在「上次审计」与「本次审计」之间发生了变化，而用户不知情。它是「装前检测」最大的盲区——审计是一次性的，依赖却是持续变化的。

`dsh-trust` 的实现：

1. **首次审计**：把每个插件的依赖清单写入基线快照（profile 目录下的 `.dsh-trust-baseline.json`）。
2. **后续审计**：对比当前依赖与基线，区分「新增 / 移除 / 版本变化」。
3. **新增依赖** → 提升为可疑并告警「dependencies added since last audit」。
4. **确认无问题后**：用 `audit_plugins` 传 `updateBaseline: true`，接受当前状态为新基线。

> 典型场景：插件作者更新版本时偷偷塞入一个恶意依赖，漂移检测会在你下次审计时把它揪出来。

## 设计边界与安全说明

- **确定性启发式，非完整静态分析**：只读 `package.json` + `cordis.patch.yml` 并 grep 入口模块的 `inject`，不逐行解析全部源码，也不查漏洞库。
- **仅告警，不拦截**：`dsh-trust` 只提示风险，不阻止安装或运行任何插件。安装来源请自行信任。
- **硬拦截不在能力范围内**：`dsh plugin add` 底层直接转发 pnpm，无安装前钩子，纯插件无法在安装那一刻强制阻断（需改官方 CLI 或接入插件市场弹窗）。

## 项目结构

```text
dsh-trust/
├── lib/
│   ├── index.js       # host 入口：注册 audit_plugins 工具 + 路由
│   ├── audit.js       # 审计核心：枚举、解析、风险计算、依赖漂移
│   └── route.js       # /trust/audit.json HTTP 数据通道
├── src/client/index.tsx  # 浏览器半区：设置页「安全审计」面板
├── scripts/build-client.mjs  # esbuild 打包 client bundle
├── cordis.patch.yml  # bundle 挂载层
└── package.json      # manifest（dsh.bundle + dsh.client）
```
